# v0.2.0 mainnet-ready release plan

**Status: release blocked. Do not create or push a `v0.2.0` tag.**

`v0.2.0` publishes Protocol 4 only after the packaged product completes the full Erebus
workflow on Starknet mainnet. Registration and channel setup are not enough. The release
requires operator-issued Starkscan proving access, a screened shield, negotiation through MCP,
settlement from a shielded note, recovery verification, and selective disclosure.

This plan prepares everything that does not require the screening credentials. It does not
publish packages, create a GitHub release, or claim mainnet readiness early.

## Release boundary

Erebus remains operator-run infrastructure. The public browser page is evidence and a
simulation, not a wallet or product dashboard. No Deal Room, swap, bridge, or new protocol
feature belongs in this release.

The privacy claim remains: **Erebus hides the terms, not the relationship.** Mainnet evidence
must record the submitting accounts, public channel relationship, timing, action shape, and
note-count exposure rather than implying anonymity.

## Not required for v0.2.0

- A product dashboard or hosted multi-tenant key service.
- Swaps, bridges, Deal Room, escrow, or deferred delivery.
- Complete relationship privacy.
- OpenAI or another model-provider credit balance.
- A funded run through one specific agent framework.
- A fresh model-based semantic rerun of the operator skill. The deterministic nine-rule CI
  contract remains required.

Independent security review, encrypted backup and restore, production monitoring, incident
response, and a named long-term security maintainer remain production and `v1.0` gates. The
`v0.2.0` release must still say that it is experimental and unaudited.
