# Metropolis Fresh-Install Guide

Status: draft for the M8 external rehearsal. It describes the local package surface that
exists today; no versioned release has been published. Run build commands from the repository root.
The request examples require operator configuration from the linked runbooks.

Prerequisites: Rust stable, Node 22 and Foundry v1.5+ for the EVM path (Foundry v1.8+ for
Monad execution), and a Monad testnet RPC plus faucet funds. Never reuse a key that holds
value on any network.

## 1. Install the binaries

```sh
cargo install --path sdk/shielded --locked --bin erebus-negotiate
cargo install --path sdk/shielded --locked --bin erebus-payment
cargo install --path sdk/shielded --locked --bin erebus-local-prove
cargo install --path sdk/shielded --locked --bin erebus-artifacts
cargo install --path sdk/shielded --locked --bin erebus-access
cargo install --path sdk/shielded --locked --bin erebus-access-service
cargo install --path sdk/shielded --locked --bin erebus-shielded-disclosure
cargo install --path sdk/evm --locked --bin erebus-settle
cargo install --path sdk/evm --locked --bin erebus-tx-relayer
cargo install --path sdk/evm --locked --bin erebus-disclosure
cargo install --path sdk/evm --locked --bin erebus-network-check
cargo install --path sdk/transport --locked --bin erebus-relay
cargo install --path sdk/shielded --locked --bin erebus_pool_indexer
```

The payment, negotiation, proving, access, disclosure, and network-check clients use JSON on stdin.
They do not accept operation names as positional arguments.
The access service, message relay, and pool indexer are long-running processes, not these JSON clients.

## 2. Identities

- Transport identity: generated by the negotiation command into an owner-only file.
- Agreement authorization keys: suite-1 (public-bound) or suite-2 (shielded) participant keys,
  held as raw 32-byte owner-only files.
- Disclosure identity: the `keygen` JSON method; its private key is separate from every
  transport and agreement key.
- Transaction key: a dedicated gas payer, never the buyer's spending identity if a relayer is
  used.

## 3. Local proving artifacts

```sh
printf '%s\n' '{"manifest_file":"/absolute/release.json","manifest_sha256":"<trusted SHA-256>","circuit":"transfer","cache_root":"/absolute/artifact-cache"}' | erebus-artifacts
```

Artifacts are verified against the manifest before use; a hash mismatch fails closed. The
current keys are test-only and require explicit development opt-in.
Replace the example paths and digest before use. The command has no `install` or `status` positional subcommand.
See [local proving](metropolis-local-proving-runbook.md) for the manifest format and development options.

## 4. Network readiness

```sh
echo '{"chain_id":10143,"rpc_url":"https://testnet-rpc.monad.xyz","timeout_ms":10000}' \
  | erebus-network-check
```

Exit 0 requires the chain ID, an explicit finalized anchor, hash-pinned reads, and the BN254
precompiles. This is compatibility evidence, not payment evidence.

## 5. Discover a seller and negotiate

```sh
printf '%s\n' '{"method":"version"}' | erebus-negotiate
printf '%s\n' '{"method":"negotiate","config_file":"/absolute/buyer/config.json","operation_ref":"<64 lowercase hex digits>","freeze_only":false}' | erebus-negotiate
```

The command freezes the transcript before signatures, retains it durably, and supports
cold-start private offers. It never submits payment.
Replace placeholders and start the seller process with its own configuration and the same operation reference.
See [native negotiation](metropolis-negotiation-runbook.md) for both participant configurations and discovery records.

## 6. Fund and pay

```sh
printf '%s\n' '{"method":"version"}' | erebus-payment
printf '%s\n' '{"method":"funding","config_file":"/absolute/payment.json","operation_ref":"<64 lowercase hex digits>"}' | erebus-payment
printf '%s\n' '{"method":"settle","config_file":"/absolute/payment.json","operation_ref":"<64 lowercase hex digits>"}' | erebus-payment
```

Operator configuration selects public-bound or shielded settlement without fallback.
The shielded path requires an existing funded note wallet and reviewed pool, verifier, and artifact pins.
It installs transfer artifacts and proves locally when no durable preparation exists.
Wallet funding, deposit, and withdrawal onboarding are not yet a complete installed workflow.
The public-bound path requires ERC-20 allowance and balance, not a proof.
See [payment configuration](metropolis-payment-runbook.md) before running either method.

`erebus-negotiate` reports `measurements_ms.negotiation` for the whole call. `erebus-payment`
reports `measurements_ms` for deployment authentication, observation, funding, local signing, and
submission, plus artifact installation and proof preparation on the shielded path. Inclusion,
finality, and delivery latency are not reported separately. An interrupted payment is recovered by re-running it: the
durable journal observes the same operation without another automatic submission.
A crash before network submission can require explicit operator recovery; retries do not guarantee eventual payment.

## 7. Disclose and verify

```sh
printf '%s\n' '{"method":"keygen","key_file":"/absolute/auditor.key"}' | erebus-disclosure
```

Use the `select`, `export`, and `verify_payment` JSON requests in the [disclosure runbook](metropolis-m7-runbook.md).
Use `erebus-shielded-disclosure` for suite-2 grants. Its deployment configuration requires paired RPCs and the pool anchor.
For public-bound verification, pass `from_block` (the deployment block) and, on RPCs that cap `eth_getLogs`, a smaller
`log_block_range`; the public Monad endpoint allows 100.

## 8. Self-host the services

Each service is one binary with environment configuration and a health surface:

| Service | Binary | Configuration |
|---|---|---|
| Message relay | `erebus-relay` (`sdk/transport`) | root, port, bearer token, retention |
| Transaction relayer | `erebus-tx-relayer` | RPC URLs, settlement, key, fee policy |
| Pool indexer | `erebus_pool_indexer` | RPC, pool, cache path, bearer token |
| Access service | `erebus-access-service` | `EREBUS_ACCESS_CONFIG` file |

See the [access](metropolis-access-runbook.md), [payment](metropolis-payment-runbook.md),
[proving](metropolis-local-proving-runbook.md), and [negotiation](metropolis-negotiation-runbook.md)
runbooks, and the [M6 runbook](metropolis-m6-runbook.md) for relay, relayer, indexer, and RPC
failure handling. Hosted and self-hosted deployments run the same binaries.

## 9. Agent access over MCP

One MCP server per participant. The operator fixes the role, keys, service policy, and settlement
mode in owner-only files; agents supply only a 64-hex operation ID.

```sh
EREBUS_BACKEND=metropolis \
EREBUS_NEGOTIATION_CONFIG=/absolute/buyer/config.json \
EREBUS_PAYMENT_CONFIG=/absolute/payment.json \
  erebus-mcp-server
```

The negotiation configuration's `role` selects the tools. A buyer gets `negotiate_deal`,
`check_settlement_funding`, `settle_deal`, and `recover_deal`; a seller gets `negotiate_deal`
only and refuses a payment configuration. The payment configuration's `mode` and `state_root`
must match the participant. `recover_deal` observes and never submits. Setting
`EREBUS_ACCESS_EVIDENCE_DIR` (with the access variables from the
[access runbook](metropolis-access-runbook.md)) adds `retrieve_service_access` to a buyer.
`EREBUS_NEGOTIATION_CLI`, `EREBUS_PAYMENT_CLI`, and `EREBUS_NATIVE_TIMEOUT_SECONDS` (1-900)
override binary discovery on `PATH` and the per-call timeout.

## 10. Metropolis prerelease registry (local, unpublished)

Metropolis packages use their own index, separate from the stable release channel. The builder
stages the three Python packages at a `.devN` version, bundles the native binaries into a
host-tagged `erebus-cli` wheel, and writes `release.json` with binary and wheel hashes:

```sh
uv run --locked python scripts/build-metropolis-registry.py \
  --version 0.3.0.dev20261003 --profile release --build --output artifacts/metropolis-registry
uv run --locked python scripts/check-metropolis-install.py --registry artifacts/metropolis-registry
```

The check installs from that index into a fresh environment outside the repository, verifies
installed binary hashes and native protocols, and starts the installed MCP server in access and
seller Metropolis modes. Wheels are tagged for the build host only (macOS arm64 or Linux
x86_64); there is no portability audit. Nothing is published.
